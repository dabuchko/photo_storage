# Developer documentation

The developer documentation consists of two parts: backend documentation and frontend
documentation.

## Backend documentation

Before running any program, all python dependencies should be installed.
The list with requirements can be found in [requirements.txt](../requirements.txt)
located in the root directory of the current repository, this can be done by:

```
pip install -r requirements.txt
```

The central part of the backend is API which is handled by [/backend/main.py](../backend/main.py). The
[/backend/main.py](../backend/main.py) uses a [/backend/predict.py](../backend/predict.py) to
generate caption for the images and classify images among albums. The
[/backend/predict.py](../backend/predict.py) itself uses a model to generate
these predictions stored in [/backend/model.pt](../backend/model.pt) and
initially generated by [/backend/train.py](../backend/train.py).

For the general user, it should be sufficient to just run API server, the instruction
on how to do this is provided in the following section.

### API (main.py)

File [main.py](../backend/main.py) is a python file that provides Flask API methods
that handle all incoming requests according to the [API specification](API_doc.md).

The API can be launched by using:

```
cd backend
python main.py
```

The user may choose to modify some basic arguments in the program which can be done
by supplying the previous command with the appropriate arguments. The instruction
containing arguments that can be changed and their format can be found by executing:

```
python main.py --help
```

More detailed documentation regarding exact functions in [/backend/main.py](../backend/main.py) can be found
in [/backend/docs/main.html](../backend/docs/main.html).

As for the interraction with API, the documentation with the description of all
API endpoints is provided in [API specification](API_doc.md).

### Training caption generation and album classification model (train.py)

[/backend/train.py](../backend/train.py) is a python script that trains a model
for caption generation using the PyTorch framework. The model itself consists
of CLIP model, with fixed (non-trainable) weights, that generates embedding
for every input image. Then the embedding is passed to MLP with single
hidden layer activated by ReLU function. The embedding generated by MLP
is used as the embedding of the first 10 characters of the GPT-2 model.
The weight of the GPT-2 model are also fixed (non-trainable). The training
is performed on COCO dataset with augmentation of the input images by applying
AutoAugment function provided by the torchvision library. For training
Adam optimizer is used with Cross-Entropy loss.
The warmup for the first 3000 steps is used.

An already trained model is stored in the [/backend/model.pt](../backend/model.pt) file and there is
no reason to train it again. However, if user decides to do this the instruction on
how to do this is provided.

The training process with defaut arguments can be started by running the following command
in the backend directory:

```
python train.py
```

The training with custom arguments can be started. Same as before, the instructions
regarding the valid comand-line arguments can be seen after executing:

```
python train.py --help
```

More detailed documentation regarding classes and functions in [/backend/train.py](../backend/train.py) can be found
in [/backend/docs/train.html](../backend/docs/train.html).

### Generating caption for the image and its classification among albums (predict.py)

[/backend/predict.py](../backend/predict.py) is a python script that loads the
pretrained model and provides a class that for every image generates a caption
and classifies it among the provided classes.

It may be beneficial for testing purposes to directly interract with file
[/backend/predict.py](../backend/predict.py) to generate caption for some image and classify image
among albums. To do this the path to the target image and album names
should be provided. Image path is the first argument, every next argument is the
name of the album. The command should be executed in the "backend" folder.

```
python predict.py images/1.jpg Dogs Cats People Bears Pigeons ABC
```

For the caption generation, model from [/backend/model.pt](../backend/model.pt) is used, it is expected to be
an instance of ImageToTextModel from [/backend/train.py](../backend/train.py). For the album matching,
CLIP model generates embeddings for images and album names in the shared latent space,
then cosine similarity finds the closest album to the provided image. If the cosine
similarity with the closest album exceeds album matching threshold, then it is
assumed that no album matches the image close enough.

Cosine similarity and path to the model for image generation can be changed
by utilizing the appropriate comand-line arguments. The detailed information about
this can be found by executing:

```
python predict.py --help
```

More detailed documentation regarding classes and functions in
[/backend/predict.py](../backend/predict.py) can be found
in [/backend/docs/predict.html](../backend/docs/predict.html).

### Database

[/backend/database.db](../backend/database.db) is a file that stores SQLite3 database. The
[/backend/main.py](../backend/main.py) script interracts with it, storing the required content.

The database instance is called "photo\_storage" and includes the following tables:

- users - keeps record of every registered user. It includes the following columns:

    * id - unique INT identificator of the user

    * username - TINYTEXT representing unique username chosen by user during account registration

    * password - BINARY(16) md5 hash password from user's account

- albums - keeps a record of every album of every user. It includes the following columns:

    * id - unique INT identificator of the album
    
    * user - INT identificator of the owner of the album, this is the same entry as id from the "users" table
    
    * name - TINYTEXT name of the album

- photos - keeps a record of every photo. It includes the following columns:

    * id - unique INT identificator of the photo
    
    * album - INT identificator of the album to which photo belongs
    
    * image - TINYTEXT filename of the uploaded photo
    
    * caption - TEXT field for storing description of the image
    
    * date - DATETIME when image was uploaded

    * name - TEXT field containing the original filename of the uploaded file

## Frontend documentation

Frontend uses HTML, CSS, and Javascript. In addition, Bootstrap framework is
used for CSS and Vue JS framework for Javascript.

The frontend consists of four html files:

* [/frontend/index.html](../frontend/index.html) - Main page that proposes user to login or sign up.

* [/frontend/login.html](../frontend/login.html) - Login page where user can login, the login form is
mainly handled by [Login.vue](../frontend/src/components/Login.vue).

* [/frontend/signup.html](../frontend/signup.html) - Sign up page where user can register, the sign up
form is mainly handled by [Signup.vue](../frontend/src/components/Signup.vue). 

* [/frontend/app.html](../frontend/app.html) - The core app performing the main functionality. It includes
navigation among albums, photo displaying, photo uploading, search, photo
and album managment operations (modification, deletion), account settings.
Consists of two parts:
    * Sidebar (its content is handled by [Sidebar.vue](../frontend/src/components/Sidebar.vue))
at the left. It navigates the user between albums, handles album managment, photo
uploading and user's account settings.
    * Gallery (its content is handled by [Gallery.vue](../frontend/src/components/Gallery.vue))
at the right. It displays all photos for the selected album or search query, performs
search, displays all information for the selected photo and performs all operations
over the photo.

There is one css file [main.css](../frontend/public/files/css/main.css) which contains all
common classes that can be reused across whole application. CSS classes that
can be applicable only to exact HTML or Vue file are kept in that file.
And overall usage of Bootstrap classes is preferred.

### [API.js](../frontend/src/assets/API.js)

Handles the requests to the API in according to the API documentation. The API
base is taken from the global `__API_BASE__` variable calculated at the compile
time from the [/config.json](../config.json) from the repository root.

Every function has a proper documentation in its [file](../frontend/src/assets/API.js).

### [Login.vue](../frontend/src/components/Login.vue)

Displays login form, handles its submission, errors that occur during the
submission and in case of success saves the authorization token in the local
storage and redirects user to the "/app".

More detailed documentation about the file functionality is provided in its
documentation comments.

### [Signup.vue](../frontend/src/components/Signup.vue)

Displays registration form, handles its submission, errors that occur during the
submission and in case of success saves the authorization token in the local
storage and redirects user to the "/app".

More detailed documentation about the file functionality is provided in its
documentation comments.

### [Sidebar.vue](../frontend/src/components/Sidebar.vue)

Handles the panel with the list of the albums. The user can select which album
to see, click on it, and then user will be redirected to hash with album id.
The currently selected album is highlighted by blue, if no album is selected,
none of them is highlighted. Each displayed album has an options menu that
can be opened by clicking on three dots shown near the album name. By clicking
on these three dots, the option menu is shown, in this menu only two options
are available: "Rename album" or "Delete album". Choosing any of those options
launches either [RenameAlbum.vue](../frontend/src/components/album_managment/RenameAlbum.vue)
or [DeleteALbum.vue](../frontend/src/components/album_managment/DeleteAlbum.vue),
with the vue model attached to the component in according to the documentation
comments for "RenameAlbum.model" and "DeleteAlbum.model".

Also sidebar contains an option to create the album. When button is clicked, the
new album
with the first available name is created chosen from the sequence formed as follows:
New album, New album 1, New album 2, ...

There is also a button to show Settings form to change the Settings. Click on these
button shows the content of the [Settings.vue](../frontend/src/components/Settings.vue).

And there is an upload button, which shows the form from the [Upload.vue](../frontend/src/components/Upload.vue).

More detailed documentation about the file functionality is provided in its
documentation comments.

### [RenameAlbum.vue](../frontend/src/components/album_managment/RenameAlbum.vue)

Pops up a form where user can change the name of the album. The album
that needs to be changed should be set in Vue model of the current component
in a way described by the `RenameAlbum.model`.

More detailed documentation about the file functionality is provided in its
documentation comments.

### [DeleteALbum.vue](../frontend/src/components/album_managment/DeleteAlbum.vue)

Pops up a form where user can delete the selected album. The album
that needs to be deleted should be sent in the Vue model for the current component
in a way described by the `DeleteAlbum.model`.

More detailed documentation about the file functionality is provided in its
documentation comments.

### [Settings.vue](../frontend/src/components/Settings.vue)

Pops up a settings menu that includes:

* "Username change" form that updates username and if update is successful also
updates the authorization token from the local storage. In case of the error it is
displayed, in case success the success message is shown and settings pop up closes.

* "Password change" form that updates password and if update is successful also
updates the authorization token from the local storage. In case of the error it is
displayed, in case success the success message is shown and settings pop up closes.

* "Download all metadata" button that downloads all metadata of every user's photo.

* "Delete an account" button that deletes user account. In case of successful deletion,
the authorization token is deleted from the local storage and user is redirected to the
"/login" page.

More detailed documentation about the file functionality is provided in its
documentation comments.

### [Upload.vue](../frontend/src/components/Upload.vue)

Pops up the uploading form. User can upload unlimited amount of images,
set albums for them, change their initially pregenerated caption and delete
the previously uploaded photo in case of mistake.

The photo can be uploaded by clicking on the uploading area of by using drag-and-drop
and dropping files in the dedicated uploading area.

In order to save modifications to the caption and album choice, the changes must
be saved by clicking "Save changes" button.

More detailed documentation about the file functionality is provided in its
documentation comments.

### [Gallery.vue](../frontend/src/components/Gallery.vue)

Has a search bar at the top that on "Enter" hit redirects user to the hash with
search requested prefixed by "search:" string.

Below the search bar the images are displayed according to the requested album
or search request, extracted from the current link. The images are loaded
continiously as soon as user reaches the end of the page. By clicking on image,
it will be shown using the [ImageViewer](../frontend/src/components/ImageViewer.vue)
component.

More detailed documentation about the file functionality is provided in its
documentation comments.

### [ImageViewer.vue](../frontend/src/components/ImageViewer.vue)

Displays selected image. The image is selected by making an appropriate
change in the Vue model attached to the ImageViewer in according to "ImageViewer.model"
documentation. The user can navigate among images using mouse or keyboard,
it can go to the next or the previous photo. Also some options are available
to making changes to the displayed photos, it is possible to edit caption,
download image, download image metadata, and delete the image.

More detailed documentation about the file functionality is provided in its
documentation comments.
