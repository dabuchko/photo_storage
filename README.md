# Photo Storage

Photo Storage is a web application for the private photo storage. It allows
users to upload their images to the website, keep them safely, and access them
in any time from any device which have access to the Internet. Besides typical
features that other similar applications have, our application stores a description
for every image, furthermore, such description is generated automatically by
default. Our application also allows to export all the generated descriptions
and other metadata of the stored images. Such approach is especially beneficial
for people working with large amount of photos, for example site owners while
working with huge amount of images this service may help to save lot of time
by automatically generating caption for every image.
In this application authenticated users can upload images, access uploaded
images, and delete them. Each uploaded image is stored with a short description
initially generated by a Neural Network model, however users can change this
description at any moment. Additionally, application implements a text-based
search among images based on their description.
The user can upload image in variety of formats: png, jpeg, jpg, webp, svg, or
gif format. Users can upload images individually, in bulk (by selecting multiple
images or folder on local computer), or by uploading a zip file containing images.
Users can also create albums (groups of images). Each image either do not
belong to any album or belong to exactly one album. Images initially can be
added to some album during upload, users can also request a Neural Nework
model to suggest albums for uploaded images. Images can be moved between
albums, and albums can be deleted or renamed.
Additionally it is possible to download all the metadata of all images either
across whole account or from the selected folder.

> Due to the limited budget, finetuning of the GPT2 model was performed for small number of epochs. For this reason the model can be imprecise and it is highly recommended to replace the model at backend/model.pt with more precise model.

## Installation

1. Clone the current repository to your local machine. And navigate to the root directory of the project.

At this point user can modify configuration files to use own parameters. The next
section descibes all configuration files and parameters that they support.

2. Ensure that Docker is installed on your machine. If not, please follow the instructions from the official Docker website:
https://docs.docker.com/get-docker/

3. Build the docker image from the Dockerfile. You can do this by running the following command in
the root of the repository:

```
docker build -t photo_storage .
```

4. Run the docker container with the following command:

The port arguments may differ if there was some related changes to the configuration files.

```
docker run -p 80:80 -p 5000:5000 photo_storage
```


## Configuration files

There are three main configuration files the user may be interested in, all
located at the root of the repository:

* [backend_config.cfg](backend_config.cfg) - configuration with parameters for
launching API server. It must contain the following parameters:
    
    * `https` - boolean on whether to use https protocol (true) or http (false).
    
    * `host` - what host API server should listen.
    
    * `port` - what port API server should listen.
    
    * `path` - base path for API endpoints.
    
    * `debug` - launch server in the debug mode (true), in this case development server
      will be used in the debug mode. If false, production server will be used.
    
    * `database_path` - relative path to the database from current working directory.
      When docker container is run, root of the repository is the default working directory.
    
    * `secret_key` - string secret key which will be used to generate the authorization tokens.
    
    * `token_expiration` - in how many seconds the issued token should expire.
    
    * `model_path` - relative path to the saved model from current working directory.
    
    * `album_matching_threshold` - the float threshold in the range between 0 and 1 of
      maximum cosine distance to classify uploaded photo among albums. If threshold
      is passed for every album-photo pair, the photo remains unclassified.
    
    * `pred_batch_size` - batch size that is used for generating captions and classifying
      images among folders during uploading multiple images to the server.

* [frontend_config.json](frontend_config.json) - configuration with parameters for
launching Vue application. It must include the following:
    
    * `api_https` - boolean on whether to use https protocol (true) or http (false)
      while accessing to API.
    
    * `api_host` - string host address where API can be reached.

    * `api_port` - integer port where API can be reached.

    * `api_path` - base path prefix for every API endpoint.

* [nginx.conf](nginx.conf) - the nginx configuration file which setups the
Nginx server to display Vue application. It should be edited in according
to the Nginx official documentation and Vue instructions to display Vue application
content.

NOTE: `https`, `host`, `port`, `path` from the `backend_config.cfg` must be consitent
with `api_https`, `api_host`, `api_port`, `api_path` from `frontend_config.json`.
Unless some modifications were done to `nginx.conf` to create an alias for API,
then this alias can be used in the `frontend_config.json`.
